# Task 1.1 – Functional Requirements

> Question: Identify 10 Functional Requirements (FRs). Record in the format:
> Req. ID | Requirement | Type | Priority | Verification Method.

**Priority key:** Critical = safety or life risk · High = core feature · Medium = important, not blocking

| Req. ID | Requirement | Type | Priority | Verification Method |
|---|---|---|---|---|
| FR-01 | The system shall require operators to log in with username, password and a one-time code before using Mission Control. | FR | High | Test |
| FR-02 | Only authenticated operators shall be permitted to issue robot commands. Every command is checked for a valid session and a valid robot state; rejected commands are logged with a reason. | FR | Critical | Test |
| FR-03 | The robot shall follow only these state changes: IDLE → NAVIGATING → (AVOIDING_OBSTACLE ↔ NAVIGATING) → DELIVERING → RETURNING → IDLE. If battery falls below 25 % while navigating, it shall abandon the delivery and return to the warehouse. | FR | High | Analysis + Test |
| FR-04 | When an obstacle is detected, the robot shall stop, switch to AVOIDING_OBSTACLE and re-route. If the path stays blocked for more than 2 minutes, it shall alert Mission Control. | FR | High | Test (simulation) |
| FR-05 | The chamber shall record temperature, humidity, vibration, door status and power every 10 seconds, linked to the medicine batch ID. | FR | High | Test |
| FR-06 | If temperature or humidity goes out of range, the chamber shall start correction automatically and confirm by sensor reading that the value is back in range within 10 minutes. | FR | Critical | Test |
| FR-07 | The chamber door shall unlock only at the destination clinic after a valid PIN or QR scan. Every door open and close shall be logged. | FR | High | Test + Demonstration |
| FR-08 | The robot shall enter Safe Mode when battery is below 10 %, chamber temperature is critical, or a critical hardware fault occurs. In Safe Mode it stops at a safe spot, keeps the chamber powered and accepts only Supervisor commands. | FR | Critical | Test (fault injection) |
| FR-09 | The robot shall send telemetry every 30 seconds and log every command, state change and alarm with time, robot ID and operator ID. During link loss, logs are stored onboard and sent after reconnection. | FR | High | Test + Inspection |
| FR-10 | Before reaching a railway level-crossing, the robot shall request permission from ARLCCS and enter only after receiving a "safe to cross" signal. | FR | Critical | Test (ARLCCS simulator) |
