# Task 3.4 – Safe Mode and Link Lost Extension

> Question: Extend the model with Safe Mode (CR-01) and Link Lost states and
> decide which existing states may enter them.

## Which states may enter them

| From State | → SAFE_MODE? | → LINK_LOST? | Reason |
|---|---|---|---|
| IDLE | Yes | No | A thermal or fault problem can happen while waiting. Link loss while idle needs no action (robot is already safe at the warehouse). |
| NAVIGATING | Yes | Yes | Robot is moving, so both are dangerous. |
| AVOIDING_OBSTACLE | Yes | Yes | Robot is moving. |
| DELIVERING | Yes | **No** | Handover is local (PIN/QR). Stopping halfway would leave the door open. Logs are buffered instead. |
| RETURNING | Yes | Yes | Robot is moving. |
| LINK_LOST | Yes | — | Without supervision, any critical condition means a safe stop. |

## Extra Transitions

| T-ID | Current State + Event | Next State | Req ID | Valid? | Evidence |
|---|---|---|---|---|---|
| T13 | NAVIGATING / AVOIDING_OBSTACLE / DELIVERING / RETURNING + SafeModeTrigger | SAFE_MODE (within 3 s) | FR-08 (CR-01) | Yes | TC-08 |
| T14 | IDLE + SafeModeTrigger | SAFE_MODE | FR-08 | Yes | TC-08 |
| T15 | SAFE_MODE + SafeModeCleared (Supervisor) | RETURNING | FR-08, FR-02 | Yes | TC-08 |
| T16 | SAFE_MODE + DeliveryRequest | SAFE_MODE (command rejected) | FR-02, FR-08 | Reject | TC-04(b) |
| T17 | NAVIGATING / AVOIDING_OBSTACLE / RETURNING + LinkLost | LINK_LOST | HR-02 | Yes | TC-10 |
| T18 | LINK_LOST + LinkRestored | Previous state (NAVIGATING or RETURNING) | FR-09 | Yes | TC-10 |
| T19 | LINK_LOST + SafeModeTrigger or CriticalBattery | SAFE_MODE | FR-08 | Yes | TC-10 |
| T20 | DELIVERING + LinkLost | DELIVERING (finish handover, buffer logs) | FR-09 | Yes (design decision) | TC-10 |

## Safe Mode exit rule
Only a **Supervisor** can clear Safe Mode, and only when battery, temperature and
fault values are all normal. The robot then goes to RETURNING, not back to delivering.
